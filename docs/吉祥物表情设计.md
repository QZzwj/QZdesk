# 吉祥物表情设计（表情集 · 动效 · 交互）

目标：在不改变形象气质与界面语言的前提下，把表情从「5 张静帧 + 一个位移小动效」升级为
一套有节奏、有反馈、可扩展的**表情系统**（视觉元素 / 动画效果 / 交互逻辑三块）。
所有实现都走仓库既有管线，不引入第二套 UI 框架：

```
assets/mascot/*.png  →  tools/mk_mascot_assets.py  →  app/mascot_assets.c  →  app/ai_face.c
```

> **实现变更**：形象已改为**矢量绘制 + 参数补间**（`app/ai_face.c` 用 LVGL 对象画身体/
> 耳朵/眼睛/眉毛/嘴/腮红，表情是参数补间），上面这条位图路线（含 `mascot_assets.c`）
> 已退役。因此下面 §2 的「画布 / 眼睛锚点 / 边缘羽化」与 §6.2 的「出图」只适用于位图
> 路线，作为历史保留；§3 的表情意图、§4 的动效节奏、§5 的交互逻辑依然成立 —— 现在它们
> 对应 `ai_face.c` 的 `k_state[]` 参数表与各条动效通道。§1 的状态映射表也仍然有效
> （含 state 5 与 `confused` 无人触发这两处缺口）。

## 0. 先说 GuiGuider 的定位

GuiGuider 是 LVGL 的**界面编辑器**（拖控件、连事件、导出 C 代码），不是美术工具，因此它
**无法产出表情本身** —— 既不会替你画，也不能从一张立绘生成各表情；它里面的"动画"只是把
你已经做好的图片序列按帧播放。

它在本项目里唯一有价值的用法是**当草稿板**：把候选图丢进去看比例、手动试动画时长与曲线、
截图对齐讨论。**导出的代码不要并入本仓库**：本仓库界面是手写 C（`pages/*.c`）加自己的
缩放层（`include/scale.h`，运行时按 `/dev/fb0` 取面板尺寸）与设计令牌（`include/theme.h`），
GuiGuider 导出的是它自己的工程结构（`gui_guider.c` / `generated/` / `custom/`），两套布局
体系并存会立刻腐化（见 §6.6）。

表情图请用绘图/AI 出图工具按 §2 的规范产出，风格延续当前形象（§3 给了每个表情的画法）。

## 1. 现状盘点（改之前必须知道的）

| 层 | 位置 | 现状 |
| --- | --- | --- |

| 显示 | `app/ai_face.c` | `lv_image` + `LV_IMAGE_ALIGN_CENTER`，按 `size / QZ_MASCOT_SIZE` 等比缩放，三处尺寸 60（关于卡片）/88（主页大卡片）/164（全屏表情）共用一份资源 |
| 眨眼 | `ai_face.c` 的 `QZ_FACE_EYE_*` | 矢量眼皮覆盖层，不是换帧；仅 idle、间隔 3~6.2s 随机、闭眼 130ms |
| 动效 | `ai_face.c:344-372` | 见 §4 的现状列 |
| 文案 | `qz_face_state_text()` | 「我在听你说～ / 我在认真回答～ / 让我想一想… / 好开心见到你！ / 我好像没听懂…」 |

**触发链路（谁决定表情）**：核心每 ~1s 推一条状态报文（`QZDESK_CORE_EVENT_STATUS`），
`pages/assistant.c:236-251` 按 `event->state` 映射：

| 核心 state | 含义 | 现在的表情 | 备注 |
| --- | --- | --- | --- |
| 3 | 在线 | idle | 握手成功后回待机 |
| 5 | 聆听中 | idle | **浪费了一个状态位**，见 §3 的 listening |
| 6 | 回复中 | speaking | 4.2s 后回落 idle（`arm_state_timer`） |
| 其它 | 未就绪 / 激活中 | thinking | 激活提示也走 thinking（`assistant.c:277`） |

另外：助手回复的 `CHAT` 事件 → speaking（6s 回落）；设置页固定 happy（`pages/settings.c:1084`）；
主页大卡片固定 idle（`pages/desktop.c:188`）。**`QZ_FACE_CONFUSED` 目前没有任何调用点** ——
素材、文案、动效都写好了却永远不出现（§5.4 给了接法）。

## 2. 视觉规范（画布与锚点）

1. **画布**：正方形，主体居中；建议长边 ≥ 800px（脚本 4× 超采样后降采样）。透明底最省事；
   不透明底也行（脚本会抠，纯色/渐变棚背景都支持）。整身或胸像都可以，脚本按内容外框归一化。
2. **眼睛锚点（实测，务必遵守）** —— 眨眼是在位图上盖两条深色「眼皮」，位置取自当前形象：
   - 两眼中距 = **画布宽的 33%**（= 外缘总宽 42% − 单眼宽 9%）；
   - 眼睛所在行 = **画布高的 43%~45%**（略高于正中）；
   - 眼皮色 = 形象眼/眉的深色（小狗是 `#75442f`）。
   新形象按这个画，眨眼自适应；画得不同就改 `ai_face.c` 顶部的 `QZ_FACE_EYE_*` 五个值。
3. **一致性**：切表情时脸的大小、鼻尖高度必须一致，否则会"忽大忽小"。做法是出图时镜头固定，
   再用 `FRAMING[state] = (zoom, dy)` 逐张微调（脚本里已有该表）。
4. **配色**：形象自带色 + 界面令牌（`include/theme.h` 的 `qz_palette`）：accent `#007AFF`、
   accent tint `#E4EFFF`、思考气泡 `#E4EFFF`、浅色画布 `#E5E5EA`、深色卡片 `#1C1C1E`。
   表情本身尽量少用高饱和色，把 accent 留给"可操作"的元素（与现有 HIG 风格一致）。
5. **边缘**：主体边缘留 2~3px 羽化；`RGB565A8` 的 alpha 平面能承载，不要为了"干净"抠成硬边
   （白毛角色在蓝/白卡片上会出现锯齿）。
6. **深色模式**：卡片在深色下是 `#1C1C1E`，浅色角色要避免纯白描边、避免只靠明度区分五官。

## 3. 表情集设计

现状 5 个状态每个都保留，另建议新增 3 个（其中两个不需要碰核心，只改 UI）。

| 状态 | 视觉要点 | 使用场景 | 触发源 | 代价 |
| --- | --- | --- | --- | --- |
| `idle` 我在听你说～ | 微笑、视线略偏右上（像在看屏幕而不是看镜头） | 默认态 | 现状 | 替换原图 |
| **`listening`（新）** 专注听 | 眼睛比 idle 睁大、嘴闭成小圆、头部朝声源微倾、耳朵/毛发轻抬 | 麦克风开启期间 | **核心 state 5「聆听中」**（现在错用 idle） | 110KB + 4 处代码 |
| `thinking` 让我想一想… | 目光上飘、一手托腮；配合 3 个矢量思考气泡 | 请求已发出、等首字节 | 现状 | 替换原图 |
| `speaking` 我在认真回答～ | 张嘴（可选 2 帧口型，见 §4.5）、身体重心略前倾 | 助手回复中 | 现状 | 替换原图 |
| `happy` 好开心见到你！ | 眼睛弯成月牙、耳朵飞起、可选抱心 | 设置页、成功反馈、点击宠物 | 现状（+ §5.5 触摸） | 替换原图 |
| `confused` 我好像没听懂… | 一边眉挑高、嘴角歪、额头一个小问号 | 没听懂 / 执行失败 | **素材已有，但无人触发** → §5.4 | 接触发即可 |
| **`sleepy`（新）** 睡着了 | 眼睛半闭、头一点一点、头顶 `zzz` | 待机超时、未激活时 | UI 计时器（无需核心） | 110KB + 4 处代码 |
| **`greet`（新，可选）** 打招呼 | 抬一只手挥动、身体前倾 | 有人靠近 | 依赖 `app/face_camera.c` 的存在/人脸检测（**目前恒返回 false**，是占位） | 110KB + 代码 + 后端 |

新增一个表情要同时改四处（`mk_mascot_assets.py` 的 `STATES`、`ai_face.h` 的 `qz_face_state_t`、
`ai_face.c` 的 `state_image()` 与 `qz_face_state_text()`）；§6.5 给了把它收敛成一处（放图即可）的做法。

## 4. 动效规范

原则：只用 `translate_x/y` 与 `opa`（不申请图层缓冲），同时运行的动画 ≤ 3 条；
所有循环动效都必须能被 `qz_reduce_motion()` 关掉（现在已遵守）。

### 4.1 切换（现状，保留）
换图 + 淡入 `QZ_DUR_SMALL` 180ms + 上移 `size*5%` / `QZ_DUR_PANEL` 220ms，ease-out；
被打断时从**当前值**续接（不跳回零点），旧状态的横向摇摆会先"落回"再进新状态。

### 4.2 稳态循环（每状态一条）

| 状态 | 现状 | 建议 |
| --- | --- | --- |
| idle | 纵向呼吸 `0 → -2%size`，2000ms | 放慢到 2600ms，更像呼吸；幅度不变 |
| listening | — | 几乎静止：±0.5% 横向、4500ms。**"静止"本身是"在认真听"的信号**，不要加花哨动效 |
| thinking | 呼吸 1800ms + 三个气泡 520ms 交错 180ms | 保留；气泡改为"思考中才显示"，切走时立即清零（现状已做） |
| speaking | 快速起伏 `0 → -2%size`，420ms | 保留；若上口型帧（§4.5）则把幅度降到 1.5% 避免和口型抢注意力 |
| happy | 小跳 `0 → -3%size`，520ms | 保留，这是最"值钱"的一条：只在一次性反馈时出现 |
| confused | 左右摇摆 `∓2%size`，1200ms | 保留；幅度降到 1.5%、周期拉到 1500ms，显得"琢磨"而不是"抖动" |
| sleepy | — | 点头：纵向 `0 → -1.5%size`，3400ms，叠加一次 `opa` 到 85% |

### 4.3 一次性反馈
成功 → `happy` 900ms 后回落；失败/没听懂 → `confused` 1400ms 后回落。回落目标由调用方给
（现有 `arm_state_timer(delay, target)` 已具备该能力，把两个魔法数收进常量即可）。

### 4.4 眨眼
仅 idle；间隔 3~6.2s 随机（固定节拍会被一眼认出是循环），闭合 130ms；`reduce_motion` 或
非 idle 时跳过。新增 listening 后**不要在 listening 里眨眼** —— 闭眼和"在听"语义冲突。

### 4.5 说话口型（可选进阶）
两条路，按预算选：
- **省**：维持单帧 + §4.2 的起伏（现状）；
- **真**：`lv_animimg` 循环 2 帧（张口/闭口）4~6fps，或 3 帧循环。代价 = 110KB/帧 + 每帧
  整块重绘（164px 下软件渲染可接受，但**建议只在全屏表情模式开启**，主页 88px 卡片保持单帧）。

### 4.6 动效预算
单帧内位移 ≤ 5% 画布；不使用 `transform_scale` / `rotation` / 阴影动画（LVGL 为它们申请
整块 ARGB 图层，嵌入式堆上容易失败，`docs/UI与设计.md` 已写死该约束）。

## 5. 交互逻辑

### 5.1 优先级（高 → 低）
播放中的一次性反馈 > 说话 > 触摸反馈 > 事件反馈 > 聆听 > 待机超时 > idle。
规则：高优先级可以打断低优先级；同优先级不重启动画（避免同状态重复触发导致闪烁）。

### 5.2 时间轴
| 事件 | 表情 | 回落 |
| --- | --- | --- |
| 核心 state 6 / 助手回复 | speaking | 4.2s / 6s（现状）→ 建议统一成"最后一条语音结束 + 800ms"，做不到就取 6s |
| 核心 state 5 | listening（新） | 随状态报文自然切走 |
| 激活中 / 未就绪 | thinking | 状态变化时切走 |
| 点击宠物 | happy | 900ms |
| 没听懂 / 执行失败 | confused | 1400ms |
| 待机 5 分钟无交互 | sleepy | 触摸即醒（回 idle） |

### 5.3 新增状态的接入点
`pages/assistant.c` 的 `qzdesk_core_event()` 是唯一映射处（`event->state` → 表情）；
`state_settle()` / `arm_state_timer()` 已经实现了"显示一段时间后回落"，新增状态复用即可，
不需要改核心（Rust 侧）。

### 5.4 把 `confused` 接起来（素材现成、零成本）
判定函数放在 `assistant.c`，对核心已经推过来的文本做关键词匹配即可（核心侧不用改）：

```c
/* 没听懂 / 执行失败都从核心以 CHAT 或 TOAST 文本推过来，这里做一次轻量判定。 */
static qz_face_state_t face_state_for_text(const char *text)
{
    static const char *k_confused[] = { "没听懂", "无法", "失败", "错误", "不支持", "超时" };
    for (size_t i = 0; i < sizeof(k_confused) / sizeof(k_confused[0]); i++) {
        if (strstr(text, k_confused[i])) return QZ_FACE_CONFUSED;
    }
    return QZ_FACE_IDLE;
}
```

命中时 `apply_face_state(QZ_FACE_CONFUSED)` + `arm_state_timer(1400, QZ_FACE_IDLE)`。
（更干净的做法是核心在事件里带一个 `level/error` 字段，那属于核心侧改动，可作为后续。）

### 5.5 触摸与声音
- 点宠物：`LV_EVENT_CLICKED` → happy 900ms（120ms 内出反馈，符合"按下即响应"）；
- 长按：进入/退出全屏表情模式（现在由右上角按钮切换，宠物本身可复用该入口）；
- 说话律动升级（可选）：核心若把音频电平推给 GUI，则用音量驱动 §4.5 的帧选择或 §4.2 的幅度。

### 5.6 待接入：存在检测
`app/face_camera.c:16` 的 `qz_face_camera_start()` 恒返回 `false`（占位）。接上后端后：
有人靠近 → 亮屏 + `greet` 挥一次手 → 回 idle；人离开 → 回 idle（不做"睡着"以免误判）。

## 6. 实现步骤（可直接照做）

### 6.1 阶段 0：准备
```sh
cp -r assets/mascot assets/mascot.bak        # 备份当前素材
python3 tools/mk_mascot_assets.py --preview  # 先跑一次确认环境（需要 ffmpeg）
```

### 6.2 阶段 1：出图（不需要写代码）
按 §2 规范 + §3 的视觉要点出图，命名严格对应：`idle / happy / thinking / confused / speaking`
（新增的再加 `listening / sleepy`，并同时改 §1 表格里的四处代码）。放好后：

```sh
python3 tools/mk_mascot_assets.py --preview   # 看 tools/preview/ 的三底色预览
```
逐张核对面部大小 → 需要时改脚本里的 `FRAMING[state] = (zoom, dy)`（zoom 放大画布 = 角色变小，
`dy` 把画布中心下移的百分比）。

### 6.3 阶段 2：接入与核对
```sh
./run.sh                         # 480×320
QZDESK_PANEL=320x240 ./run.sh    # 320×240（小屏下眼睛锚点最容易暴露问题）
```
在三个尺寸上各看一遍：主页大卡片 88px、设置页"关于"卡片 60px、全屏表情 164px。

### 6.4 阶段 3：代码（§4/§5 的落地，逐条独立可做）
1. `ai_face.c`：按 §4.2 调参（纯数值）；把 §4.3 的 900/1400ms 收进常量；
2. `assistant.c`：§5.2 的映射表 + §5.4 的 `face_state_for_text()` + §5.5 的点击 happy；
3. 新增 `listening / sleepy`：`ai_face.h` 加枚举、`ai_face.c` 加图与文案、`assistant.c` 接
   state 5 → listening、加一个待机计时器 → sleepy；
4. 口型（可选）：`ai_face.c` 里把 `lv_image` 换成 `lv_animimg`，仅全屏模式建帧序列。

### 6.5 可选：把"新增表情"从 4 处收敛成 1 处
让 `mk_mascot_assets.py` 从一张表（状态名 + 中文文案 + 动效档）同时生成
`mascot_assets.h` 里的枚举与 `ai_face.c` 用的映射表，此后新增表情只需要"放一张 PNG + 跑脚本"。
建议在表情集定稿后再做（否则要动生成的 4MB 文件）。

### 6.6 明确不要做的事
- 不把 GuiGuider 导出的工程并进本仓库（两套布局/主题体系）；
- 不用 `transform_scale` / 旋转做表情动效（图层缓冲）；
- 不在 listening 状态眨眼（语义冲突）；不在主页卡片上播逐帧口型（省 CPU）；
- 不为每个表情单独换构图（脸大小必须一致，否则切换时跳）。

## 7. 验收清单
