# 液态玻璃风格：LVGL 迁移方案与 RV1106 性能取舍

配套的可运行参考实现：[`tools/liquid-glass-demo.html`](../tools/liquid-glass-demo.html)
（HTML + CSS + 原生 JS，无框架，浏览器直接打开；带可调参数面板与 FPS 计量，
低/中/高三档质量对应本文的三档取舍）。本文不复制原站任何代码，视觉特征按
「折射 / 色散 / 菲涅尔 / 高光 / 模糊 / 阴影 / 超椭圆 / 形变」八项自行实现。

## 一、浏览器版用了什么（作为迁移的基准）

| 特征 | 浏览器实现 | 为什么便宜/贵 |
| --- | --- | --- |
| 折射 | 背景克隆层以玻璃中心为不动点放大（transform）+ SVG `feDisplacementMap` 边缘弯折 | 克隆层只碰 transform（合成器）；位移贴图是 GPU 滤镜 |
| 色散 | 玻璃边缘红/青两道细条纹（inset box-shadow） | 几乎零成本，但只有边缘没有全域通道分离 |
| 菲涅尔 | conic-gradient 圆环，mask 抠成 2px 贴边 | 一次性栅格化，之后零成本 |
| 高光 | 跟指针的径向亮斑 + 斜向 sheen（两个渐变叠加） | 渐变重绘仅在小层上 |
| 模糊 | feGaussianBlur（只作用于玻璃内容，非 backdrop） | GPU 滤镜；软件渲染下最贵的一项 |
| 阴影 | box-shadow | GPU 模糊；软件渲染下贵 |
| 超椭圆 | JS 生成 `clip-path: path()`，参数变化才重建 | 参数不变零成本 |
| 形变 | 弹簧积分（固定子步长）→ 只写 transform | 每帧一次 transform 提交 |

关键结论：浏览器里"玻璃感"的**大部分来自静态层**（rim / 高光 / 色散边 / 染色 / 阴影），
**动态的只有折射、模糊、形变三样**。这个比例正是 LVGL 迁移的依据。

## 二、LVGL 的可行路径

LVGL 9 没有 backdrop-filter（没有"取我身后的像素来处理"的管线），所以
**"透过玻璃看背景"必须换一种生产方式：预烘焙**。

### 2.1 总体架构：一张烘焙玻璃贴图 + 三个动画

```
构建期（host 上跑 tools/ 里的烘焙脚本）：
  背景 → 高斯模糊 → 与玻璃形状做超椭圆裁剪 → 叠 rim/高光/色散边/染色
  → 输出一张 ARGB8888 玻璃贴图（玻璃区域不透明，边缘 2~3px 羽化）

运行期：
  lv_image(玻璃贴图)                     ← 折射+模糊+高光全部"已发生"
    ├─ lv_anim: style_translate          ← 漂浮/拖拽（液体位移）
    ├─ lv_anim: style_transform_scale    ← 捏一下（挤压拉伸，LVGL 9 走 layer）
    └─ lv_anim: style_opa                ← 出入场交叉淡化
```

这张贴图在 LVGL 里就是 `lv_image_dsc_t`（ARGB8888 或 RGB565A8，见体积预算），
玻璃形状、超椭圆、rim、高光、色散**全部固化在里面**，运行期零绘制成本。

### 2.2 效果对应表（CSS/浏览器 → LVGL）

| 视觉特征 | 浏览器做法 | LVGL 做法 | 档位 |
| --- | --- | --- | --- |
| 折射 | 克隆层缩放 + feDisplacementMap | **烘焙进贴图**（烘焙时把背景在玻璃区域内放大 5~8% 再合成）；动画中玻璃位移时贴图整体跟着走，折射不实时更新 | 降级 |
| 色散 | 边缘红/青 inset 条纹 | 同样**烘焙**（贴图边缘 1~2px 红青渐变）；或运行期在玻璃 lv_obj 上叠 1px 两圈 `border_color` 渐变近似 | 保留（烘焙）/砍（实时） |
| 菲涅尔 | conic-gradient 圆环 | **烘焙**；运行期近似：`lv_obj_set_style_border_color` + 上下两段不同透明度（顶亮底暗）| 保留 |
| 高光 | 跟指针径向亮斑 + sheen | **烘焙静态高光**（固定左上 30% 处）；跟指针版本需要每帧重绘渐变层，只允许在 ≤120×120 的小玻璃上用 `lv_canvas` 局部重画 | 保留（静态）/砍（跟指针） |
| 模糊 | feGaussianBlur | **烘焙**（背景模糊图）；若背景是纯渐变，直接用 LVGL 渐变 style 画"本来就糊"的背景，成本为零 | 保留（烘焙） |
| 阴影 | box-shadow | `lv_obj_set_style_shadow_width/spread/opa`（LVGL 软件渲染有实时高斯模糊阴影，**贵**）→ 改用**烘焙的阴影贴图**垫在玻璃下 | 降级 |
| 超椭圆 | clip-path path() | 烘焙进贴图 alpha；矢量方案只能 `lv_obj_set_style_radius`（圆角，非超椭圆） | 保留（烘焙） |
| 形变 | 弹簧 → transform | `lv_anim` 驱动 `translate_x/y`（最便宜）+ `transform_scale`（LVGL 9 会把该对象升到 layer，**限小面积**）+ `opa` | 保留（限定属性） |
| 染色/毛玻璃白 | rgba 白覆盖 | `lv_obj_set_style_bg_color/bg_opa` 一层半透明白 lv_obj，直接保留 | 保留 |

### 2.3 必须砍掉的（LVGL 结构性做不到，不是参数问题）

1. **实时 backdrop 折射**：LVGL 没有"取身后像素"的管线；玻璃移到哪里，折射内容
   就该变到哪里——这需要每帧把玻璃下方的屏幕区域读回、变换、再合成，
   软件渲染下等于每帧多 2~3 次全帧 memcpy + 一次逐像素重采样。砍。
2. **实时逐像素色散（通道分离）**：三份位移+通道混合，成本是折射的 3 倍。砍
   （用烘焙边缘条纹表达"有色散"这件事）。
3. **动态菲涅尔（随视角变化）**：静态屏没有"视角"，烘焙固定 rim 即可。砍。
4. **实时模糊面积 > 1/4 屏**：软件盒滤波 3×3 单通道约 10~15 ops/px，
   见 §3 的预算算术。全屏模糊直接砍，小面积用预模糊贴图替代。

### 2.4 与本仓库的结合点

- `include/theme.h` 已有 `QZ_GLASS_RIM` 令牌、`app/theme.c` 已有 `qz_style_glass()`
  （toolbar 的毛玻璃）：迁移第一步就是把 `qz_style_glass()` 升级为
  "半透明底 + 顶亮底暗双色边框 + 静态高光贴图"三件套，**不引入任何逐像素操作**；
- 玻璃贴图按**运行时面板尺寸**烘焙（`qz_panel_w/h`，与 `include/scale.h` 的
  运行时面板机制一致）：同一烘焙参数出 480×320 与 320×240 两套，启动时按面板选；
- 主题切换（`qz_theme_refresh_all`）需要浅/深两张贴图，随令牌一起换。

## 三、RV1106 三档取舍

### 3.0 预算算术（为什么这么砍）

RV1106：单核 Cortex-A7 @1.2GHz（≈1.2 GMAC/s 整数）、256MB DDR3L、无 GPU、
LVGL 软件渲染直写 RGB565 fb。取 30fps：

```
帧预算        33 ms
全帧像素      480×320 = 153,600 px（0.3 MB RGB565）
全帧 memcpy   ≈ 1~2 ms（这是地板，任何全帧操作先扣这么多）
全帧 50% alpha 混合  ≈ 2~4 ms
3×3 盒滤波(可分离, 2 pass) ≈ 12 ops/px → 全帧 ≈ 1.84M ops ≈ 3~5 ms
                              且中间结果要 RGB888/ARGB（带宽×2）
5×5 高斯 ≈ 3~4 倍于 3×3 → 全帧 10~20 ms  ← 一项就吃掉 1/3 帧
位移重采样(双线性) ≈ 8~10 ops/px → 全帧 ≈ 3~4 ms，加上读回屏幕 2 次 memcpy
大面积 transform_scale（layer 路径）= 升 ARGB 层 + 重采样 + 回混，面积线性涨
```

结论：**全帧级别只允许"memcpy + 一次混合"**；一切逐像素滤波（模糊/位移/色散）
只能发生在**烘焙期**或**≤1/16 屏的小面积**；动画只保留 translate / opa /
小面积 scale。

### 3.1 三档清单

**保留（几乎零成本，直接做）**

| 项 | 理由 |
| --- | --- |
| 半透明染色层（bg_opa 8~12% 白） | 一次 alpha 混合，面积可控 |
| 双色描边 rim（顶亮底暗 1px，或烘焙环） | 边框绘制按周长计，几百像素 |
| 静态高光渐变（烘焙进贴图或小图叠加） | 零运行成本 |
| 阴影贴图（烘焙柔影垫底） | 代替 LVGL 实时阴影 |
| `translate_x/y` / `opa` 动画 | 只改合成偏移/混合系数，无重采样 |
| 圆角 radius | LVGL 原生，按角画 |
| 弹簧手感（固定子步长积分驱动上述属性） | CPU 上是几十次乘加，可忽略 |

**降级（有效果但要换生产方式）**

| 项 | 降级方案 | 理由 |
| --- | --- | --- |
| 折射 | 烘焙放大 5~8% 的背景进玻璃贴图；玻璃移动时不更新 | 位移重采样+读回屏幕每帧 6~10 ms，且读回 fb 依赖 ioctl，代价结构上不成立 |
| 模糊 | 背景整张预烘焙成模糊图（工具期完成）；或背景本来就是渐变，直接用 LVGL 渐变 | 实时 3×3 全帧 3~5 ms 且带宽翻倍；烘焙后零成本 |
| 阴影 | LVGL 实时 shadow（小控件可用）→ 大玻璃一律烘焙阴影贴图 | 实时阴影是逐像素高斯，同模糊量级 |
| 超椭圆 | 烘焙 alpha 形状；需要矢量时退回大圆角 radius | 软件填充任意路径走 `lv_draw_label` 之外的 mask 路径，贵且无现成 API |
| 捏一下（scale 形变） | 只允许在 ≤160×160 的玻璃上用 `transform_scale`（layer 升 ARGB ≈ 100KB、混合 1~2 ms） | layer 升格面积线性涨，全屏 scale 直接出局 |
| 色散 | 烘焙边缘红青条纹（保留"有色散"的观感） | 实时通道分离 = 3×位移成本 |

**砍掉（结构性不成立）**

| 项 | 理由 |
| --- | --- |
| 实时 backdrop 折射（玻璃移到哪折到哪） | 需要读回屏幕 + 逐像素重采样 + 回混，每帧 10 ms 起且依赖 fb 读回；LVGL 无此管线 |
| 实时逐像素色散 | 3 份位移成本；观感收益集中在边缘，烘焙条纹已够 |
| 动态菲涅尔 | 静态视角下无意义 |
| 全屏/大面积实时模糊 | 一项吃掉 1/3~2/3 帧预算，且中间缓冲要 RGB888 |
| 跟指针的高光 | 每帧重绘渐变层；若玻璃 ≤120×120 可用 lv_canvas 局部重画，否则砍 |
| 每帧重建形状/路径 | 任何逐帧几何生成都禁止；形状只在参数变化时重建 |

### 3.2 最终配方（能在 RV1106 上跑的那一版）

```
静态资产（构建期烘焙，两套主题 × 两档面板尺寸）：
  glass_<theme>_<w>x<h>.bin   ARGB8888 玻璃贴图：
                              超椭圆 alpha + 折射背景(放大6%) + 高斯模糊背景
                              + rim + 高光 + 色散边 + 染色，边缘 2px 羽化
  shadow_<...>.bin            A8 阴影贴图（玻璃形状外扩 12px 高斯）
运行期每帧（玻璃漂浮时）：
  1. 把阴影贴图与玻璃贴图各画一遍（memcpy 型 blit + alpha 混合）
     —— 玻璃 200×200 时两次 blit ≈ 0.3~0.5 ms
  2. translate 由弹簧驱动（CPU 几十次乘加）
  3. 触碰反馈：opa 闪一下 / translate 弹一下（不碰 scale）
  4. 捏一下（可选）：200×200 内 transform_scale，单帧 +1~2 ms，动画 200 ms 内结束
预期：30fps 满帧有余量；玻璃拖拽时无效化区域只有玻璃新旧两块矩形。
```

成本核对：玻璃 200×200 ARGB blit = 40k px × ~10 ops = 0.4M ops ≈ 0.4 ms；
阴影 A8 混合类似。两贴图 + 无效区重绘背景（≈600×600 RGB565 memcpy ≈ 1 ms），
整帧 ≈ 2 ms，占 33 ms 预算的 6%——**余量足够把 30fps 让给业务界面**。

### 3.3 一句话版本

> 浏览器里液态玻璃 = 静态材质层（rim/高光/色散/染色/阴影）+ 三件动态
> （折射/模糊/形变）。LVGL 没有逐像素管线，就把**静态材质与折射模糊全部
> 烘焙成一张贴图**，运行期只保留 translate/opa/小面积 scale 三种动画 ——
> 这恰好也是 RV1106 预算算术允许的全部。
